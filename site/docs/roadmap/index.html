MunaSIP roadmap

Work is split into three phases; the PBX is usable at the end of each phase. After phase 1 the company can cut over from the old system.

Phase 1: Core PBX and admin panel

  • VM, Debian 13, Asterisk 24; PJSIP, ARI, AMI (Docker Asterisk 22 lab)
  • First SIP trunk; inbound/outbound test (trunk CRUD + dialplan; real trunk separate)
  • Monorepo skeleton: apps/web, apps/api, packages/shared; Biome, Vitest, CI
  • DB schema and Asterisk config writer (PJSIP realtime or files + reload)
  • Admin login, 2FA, audit log
  • UI shell: theme, layout, shadcn components, shared destination picker
  • Extensions screen: CRUD, permissions, forwarding, DND, CSV
  • Trunks and routes screens, blacklist (PATCH route + member PUT included)
  • Ring groups and queues (members, strategy, announces, overflow)
  • Schedules, holidays, manual override
  • Recording, KVKK announcement, Opus convert, retention (WAV + retention; Opus optional)
  • CDR and recordings screens
  • Security: fail2ban, country limit, spend stop, rate limit, TLS + SDES SRTP (optimistic) / WebRTC DTLS (login-guard + compose profile)
  • IP phone provisioning and QR softphone setup
  • Backup

Smoke (Phase 1): blacklist reject; after-hours schedule; 2FA; CSV; backup; SMTP/IP/KVKK; anonymous block; permissions; 112; CDR filter/timeline; DestPicker; ring group edit; internal hook secret; AMI trunk status.

Phase 2: Flow designer and user portal

  • ARI flow engine: node runner, variables, version lock
  • Designer UI: canvas, palette, node panels, validate, publish, rollback
  • API request node: template, auth, JSONPath, timeout, test
  • TTS, language, name-lookup nodes (TTS lab beep fallback)
  • Call simulation
  • Prompts screen: upload, TTS, MOH (WAV upload + MOH config)
  • User portal: login, SIP.js softphone, coturn, directory and presence
  • Portal: my calls, my recordings (listen only), voicemail, forwarding, DND

Smoke (Phase 2): IVR API+headers+Test HTTP; simulate/rollback; portal dial/directory/recent/DND init; VM; MOH; waveform player.

Phase 3: Monitoring, reports, integration

  • Live dashboard and TV mode (WebSocket)
  • Spy, whisper, barge (ARI snoop)
  • Reports: summary, queue, extension, IVR DTMF, quality (summary/IVR/extension)
  • Missed calls, “called back” tracking, email (log-only summary without SMTP)
  • Last-dial callback (12h)
  • Queue callback
  • Automatic daily and monthly report emails
  • Webhooks, integration API, API keys
  • Recording archive (NAS / SFTP) (local path copy; recordingArchivePath)

Smoke (Phase 3): Dashboard WS; spy; reports date range+quality; API key perms; webhook Test; missed tabs; SMTP; Opus convert (when ffmpeg present).

Operator setup (done in UI — not blocking code)

  • SIP provider settings — Admin → SIP providers (trunk CRUD: auth, codecs, channels, notes); DIDs via Routes
  • Recording retention months — Admin → Settings
  • Desk phone brands — Devices provisioning profiles (Yealink / Fanvil / Grandstream / softphone)
